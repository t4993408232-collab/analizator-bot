# Решения

Почему сделано так, а не иначе. Новое решение — новая запись сверху.
Решения до 2026-10-02 восстановлены по коду, коммитам и докам; если причина
не записана в источнике, так и сказано.

## D-008 · 2026-10-02 · Обвязка: два инструмента курса, общие имена файлов

- **Решение:** журнал — `progress.md`, статус фичи — поле `status`
  (not-started / in-progress / blocked / done), как в скилле harness-creator.
  `tools/audit-harness.sh` поправлен, чтобы принимать `progress.md`.
- **Почему:** скилл и audit-скрипт курса расходятся в именах (`progress.md` vs
  `PROGRESS.md`, `status` vs `state`). Два файла, различающиеся только регистром,
  ломают checkout на macOS/Windows.
- **Цена:** audit-скрипт оставляет WARN «feature_list.json contains ... state».

## D-007 · 2026-10-02 · Проверка только офлайн, три слоя

- **Решение:** `./init.sh` = компиляция → check-arch → офлайн-тесты → смоук
  приложения без внешней сети. Живой прогон — только на Render.
- **Почему:** из веб-сессии Claude и нестабильно из CI закрыты hh.ru, Telegram,
  OpenAI, УТП. Проверка, которая зависит от сети, краснеет не из-за кода.

## D-006 · 2026-10-02 · Правила ревью превращаются в автоматические проверки

- **Решение:** повторяющееся замечание из ревью → правило в
  `.harness/arch-rules.json` (WHAT / WHY / FIX), а не строчка в CLAUDE.md.
- **Почему:** правило в тексте агент может пропустить; проверка в `./init.sh` — нет.

## D-005 · Тендерный конвейер шлёт отчёт даже без OpenAI

- **Решение:** если OpenAI недоступен, отчёт уходит с сырым текстом страницы
  (см. `TENDER_PIPELINE.md`).
- **Почему:** факты о закупке ценнее анализа; дедлайн нельзя пропустить из-за API.

## D-004 · Постоянный диск для антидубля

- **Решение:** `seen_vacancies.json` / `seen_tenders.json` на диске Render
  `/var/data` (render.yaml).
- **Почему:** на эфемерной ФС антидубль теряется при рестарте → повторные
  публикации в канал (комментарий в `job_poster.py`).

## D-003 · Хостинг Render, Blueprint, план starter

- **Решение:** сервис описан в `render.yaml`, план `starter` (always-on).
- **Почему:** почасовому планировщику нужен процесс, который не засыпает
  (комментарий в render.yaml). Почему именно Render — в источниках не записано.

## D-002 · Тесты — обычные скрипты, не pytest

- **Решение:** `tests/*.py` запускаются `python tests/x.py`, печатают [OK]/[FAIL].
- **Почему:** в источниках не записано; так было с первого теста. pytest в
  `requirements.txt` нет — менять только вместе с CI.

## D-001 · Ничего не выдумывать

- **Решение:** вакансии, контакты, факты закупок — только из источника;
  пропуски помечаются «не указано».
- **Почему:** принцип №1 проекта (CLAUDE.md): канал и отчёты читают живые люди,
  выдуманный контакт или срок хуже пустого поля.
