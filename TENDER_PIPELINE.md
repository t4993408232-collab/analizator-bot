# Тендерный конвейер v1.0

Разбор закупок с УТП Сбербанк-АСТ (секция **Росатом**, 223-ФЗ/ЕОСЗ).
Конвейер берёт URL карточки закупки, скачивает страницу, извлекает факты,
делает анализ участия через OpenAI и присылает отчёт владельцу в Telegram.

Принцип №1 проекта действует и здесь: **ничего не выдумывать** — в отчёте
только факты со страницы; отсутствующие поля помечаются «не указано».

## Стадии конвейера

1. **fetch** — загрузка HTML карточки (`utp.sberbank-ast.ru/...`), с запасным
   вариантом `PurchaseView`, если `PurchaseViewResp` пуст.
2. **extract** — видимый текст страницы + XML из hidden-полей ASP.NET.
3. **structure** — OpenAI извлекает факты в JSON: номер, предмет, заказчик,
   способ, НМЦ, сроки подачи/итогов, обеспечение, требования, документы, контакты.
4. **assess** — OpenAI готовит анализ участия: суть, требования, риски,
   чеклист документов, дедлайны.
5. **report** — отчёт в Telegram владельцу (`OWNER_CHAT_ID`), антидубль по id закупки.

Если OpenAI недоступен, отчёт всё равно уходит — с сырым текстом страницы
(факты доходят без анализа). Если страница не загрузилась, владелец получает
уведомление об ошибке.

## Очередь

Очередь задаётся `TENDER_QUEUE` (URL через запятую) и обрабатывается:

- **автоматически при старте сервиса** (`TENDER_AUTORUN=1`, по умолчанию включено);
- **вручную**: `POST /tender/run` (см. ниже).

Сейчас в очереди по умолчанию:

- https://utp.sberbank-ast.ru/Rosatom/NBT/PurchaseViewResp/13/0/0/374791036

Разобранные закупки не разбираются повторно (`seen_tenders.json`;
на Render — на постоянном диске `/var/data`).

## Ручной запуск

```bash
# вся очередь
curl -X POST https://<host>/tender/run -H "X-Token: $TENDER_TOKEN"

# конкретная закупка (force — разобрать повторно, игнорируя антидубль)
curl -X POST https://<host>/tender/run -H "X-Token: $TENDER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://utp.sberbank-ast.ru/Rosatom/NBT/PurchaseViewResp/13/0/0/374791036", "force": true}'

# посмотреть очередь и уже разобранное
curl https://<host>/tender/queue
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен Telegram-бота (обязательно) | — |
| `OWNER_CHAT_ID` | чат для отчётов (обязательно) | — |
| `OPENAI_API_KEY` | ключ OpenAI (структурирование + анализ) | — |
| `OPENAI_MODEL` | модель | `gpt-5-mini` |
| `TENDER_QUEUE` | URL закупок через запятую | закупка 374791036 |
| `TENDER_AUTORUN` | прогонять очередь при старте (`1`/`0`) | `1` |
| `TENDER_TOKEN` | секрет для `POST /tender/run` (иначе берётся `JOB_POSTER_TOKEN`) | — |
| `TENDER_SEEN_FILE` | файл антидубля | `seen_tenders.json` |

## Сетевой доступ

Конвейеру нужен доступ к `utp.sberbank-ast.ru`, `api.openai.com`,
`api.telegram.org`. В песочнице веб-сессии Claude эти хосты закрыты
egress-политикой — вживую конвейер работает на **Render** (очередь
прогоняется автоматически после деплоя).

## Ограничения (честно)

- Карточка УТП может подгружать часть данных JS-запросами; тогда в тексте
  страницы фактов мало, конвейер сообщит об этом владельцу. Точка расширения —
  добавить в `fetch_purchase_html` обращение к внутренним XML-эндпоинтам УТП.
- Документация закупки (файлы) не скачивается — в отчёте только перечень
  и ссылка на карточку.
