# Оценка готовой фичи

Перед тем как считать фичу done, оценить по каждому измерению. Каждое должно
быть **A или B**; одно C или D = фича не готова, вернуть с конкретным фидбеком.
Оцениваем по выводу команд, а не по виду кода.

| Измерение | A | B | C | D |
|---|---|---|---|---|
| **Корректность** | все слои verify-feature OK | Layer 1–2 OK, Layer 3 не нужен | часть тестов красная | не компилируется / Layer 1 красный |
| **Архитектура** | `make check-arch` OK, новых паттернов нет | OK, мелкие отступления от ARCHITECTURE.md | нарушение границ, не пойманное правилом | `make check-arch` красный |
| **Тесты** | основной путь + краевые случаи | только основной путь | тест-заглушка | тестов на новое поведение нет |
| **Evidence** | evidence в feature_list.json от verify-feature | evidence вручную, с командами | «проверил» без команд | ничего не запускалось |
| **«Не выдумывать»** | все данные из источника, пропуски = «не указано» | — | дефолт выглядит как факт | выдуманные контакты/сроки/вакансии |

## Как давать фидбек

Плохо: «фича недоделана».
Хорошо: «Тесты — C. В tests/test_sanity.py нет проверки зарплаты с полем `to`
без `from`; по контракту нужно "до 100 000 ₽". Проверить: `python3 tests/test_sanity.py`.»

В фидбеке: измерение и оценка, файл/строка/вывод, ожидаемое поведение (из
контракта), команда для проверки.
